Trace Twins

Trace Twins

Did these two programs leave the same fingerprint — even in disguise?

Livia is a malware analyst. Every day, suspicious programs arrive on her desk. She runs each one in a sandbox and records what it asks the operating system to do: open files, read registry keys, allocate memory, send data over the network, and so on.

Each request is represented by a short command from a fixed vocabulary of about 270 possible commands. The full sequence of commands made by a program is called its transcript.

Example transcript:

ldrloaddll  ntopenfile  ntreadfile  regopenkey  regqueryvalue  ntclose  ...

Attackers often reuse and slightly modify old malware instead of writing completely new programs from scratch. Because of this, two transcripts may look different but still come from the same underlying program.

To make the task harder, attackers may also disguise the transcript by renaming commands to random strings. Your goal is to build a tool that decides whether two transcript fragments came from the same program or from different programs, even when command names are scrambled.

Dataset Description

You are given training data in:

public_traces.zip

After unzipping, it contains one CSV file:

public_traces.zip
└── public_traces.csv

The CSV has one row per program:

program_id,category,tokens
5080,Adware,ldrloaddll ldrgetprocedureaddress ldrloaddll ntopenfile ntreadfile ...
2913,Trojan,regopenkey regqueryvalue ntclose ldrloaddll ntcreatefile ...
...

The columns are:

  • program_id — the unique identifier of the program
  • category — the malware category, such as Adware or Trojan
  • tokens — the full transcript as a single space-separated string

Each transcript is split into pieces of exactly 200 commands. Each piece is called a window.

Two windows are considered a positive match if and only if they were cut from the same original transcript.

You are evaluated on a separate hidden set of programs. These programs are not available during training, so your solution must generalize to new, unseen programs.

Some negative pairs may be doppelgängers: two different programs from the same malware category. These programs may naturally behave similarly, which makes the task more challenging.

What You Need to Build

You need to implement two scoring functions:

def score_A(windows, pairs):
    ...

def score_B(windows, pairs):
    ...

Each function receives:

  • windows — a list of windows, where each window is a list of 200 commands
  • pairs — a list of (i, j) index pairs into windows

Each function must return:

  • one float score for each pair
  • higher score means the two windows are more likely to come from the same program

Only the ranking of your scores matters, not their exact scale.

Example

A concrete call may look like this:

windows = [
    ["ldrloaddll", "ntopenfile", "ntclose", ...],
    ["regopenkey", "ntreadfile", "regqueryvalue", ...],
    ...
]

pairs = [
    (0, 5),
    (1, 1),
    (2, 9),
    ...
]

score_A(windows, pairs)
# -> [0.93, 0.10, 0.55, ...]

The returned list must have the same length as pairs, and the scores must be returned in the same order.

Submission Format

You must submit one file:

submission.pkl

This file must contain a serialized Submission object using cloudpickle.

The starter notebook provides the required class structure. You only need to implement score_A and score_B.

import cloudpickle

sol = Submission()

with open("submission.pkl", "wb") as f:
    cloudpickle.dump(sol, f)

Your Submission class should contain:

class Submission:
    def score_A(self, windows, pairs):
        ...

    def score_B(self, windows, pairs):
        ...

The grader will load your submission.pkl, call the correct scoring function, and evaluate the returned scores.

Important Submission Notes

Build your Submission object directly inside the notebook so that cloudpickle captures the class by value.

Do not rely on importing your class from an external .py file, because that may fail in the grading sandbox.

The cloud will not retrain your solution. If your method uses a trained model, the trained model must already be stored inside submission.pkl.

Your submission.pkl file must be at most 50 MB.

Evaluation Notice

While the evaluation is running, you will not be able to use the cloud environment for other work.

Scoring

The task is evaluated using ROC-AUC.

ROC-AUC measures how often a randomly chosen same-program pair receives a higher score than a randomly chosen different-program pair.

0.5 = random guessing
1.0 = perfect ranking

The total score is:

Total score = Part A score + Part B score

Maximum total score:

100 points

Part A Scoring

Part A is worth at most 50 points.

Let:

A_A = ROC-AUC for Part A

The score is computed as:

Part A score = round(max(3, min(50, 3 + (A_A - 0.50) / 0.34 × 47)))

This means:

AUC = 0.50 -> 3 points
AUC = 0.84 -> 50 points
AUC < 0.50 -> 3 points

Part B Scoring

Part B is worth at most 50 points.

Let:

A_B = ROC-AUC for Part B

The score is computed as:

Part B score = round(max(2, min(50, 2 + (A_B - 0.50) / 0.28 × 48)))

This means:

AUC = 0.50 -> 2 points
AUC = 0.78 -> 50 points
AUC < 0.50 -> 2 points
